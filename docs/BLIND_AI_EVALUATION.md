# Blind AI evaluation

## Purpose

The **AI Evaluation** tab (formerly **Test the AI**) runs a randomized blind evaluation separate
from the WhatsApp-style chat demo. For each sample, the analyzer receives only
the message text. It records the raw ML prediction, evaluates the existing
first-contact evidence rules, records the combined warning, and only then
returns the independently stored reference label for scoring.

The production artifact is `models/job_posting_classifier.joblib`. The blind
runner does not fit, retrain, tune a threshold, or pass labels, scenario names,
sender categories, fixture IDs, or phone numbers to prediction functions.

## Current dataset and provenance

The current runner uses `data/synthetic/evaluation.jsonl`: 32 repository-authored
fictional first-contact recruitment examples, split evenly between 16 labelled
legitimate and 16 labelled fraudulent examples. There are 16 clear and 16
subtle examples. They are held out from fitting and threshold selection, and
the runner rejects normalized exact overlap with the training data.

These are synthetic demonstrations, not authentic public messages. No
independent labelled first-contact recruitment corpus is available in this
repository. General SMS spam must not be relabelled as verified job fraud. An
independent benchmark should be added only when authentic provenance, licensing,
label meaning, duplicate checks, and near-duplicate checks can be verified.

## Frozen results

Generated by `python -m scripts.run_blind_evaluation` and stored in
`reports/blind_ai_evaluation.json` using the unchanged production model.

| System | N | TP | TN | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| ML classifier | 32 | 5 | 16 | 0 | 11 | 1.0000 | 0.3125 | 0.4762 |
| Evidence rules | 32 | 9 | 8 | 8 | 7 | 0.5294 | 0.5625 | 0.5455 |
| Combined warning | 32 | 11 | 8 | 8 | 5 | 0.5789 | 0.6875 | 0.6286 |

Confusion matrices use rows actual and columns predicted in
`[legitimate, fraudulent]` order:

- ML: `[[16, 0], [11, 5]]`
- Evidence rules: `[[8, 8], [7, 9]]`
- Combined warning: `[[8, 8], [5, 11]]`

The report includes every false alarm and missed scam by sample ID. The
combined system catches more of this synthetic set than the raw model, but it
also produces eight synthetic false alarms. This is not evidence of real-world
accuracy or model improvement.

## Reproduction

```powershell
.\.venv\Scripts\python.exe -m scripts.run_blind_evaluation
.\.venv\Scripts\python.exe -m pytest -q --browser-tests
```

The evaluator's arbitrary-message endpoint intentionally returns
`reference_label: null` and is never scored. It demonstrates predictions only;
it cannot manufacture ground truth. In the app, arbitrary text is entered on the
**Test a Message** tab, which is likewise unscored; the AI Evaluation tab links
to it instead of carrying a second input box.

## Reading the screen

The tab shows each message with the three predictions marked **Correct** or
**Incorrect** against the reference label, and running totals per system:
**Correct** (TP + TN), **Missed Scams** (FN) and **False Alarms** (FP), plus
"Caught x of y scams" (recall as a count). Precision, recall and F1 remain in
`reports/blind_ai_evaluation.json` and the table above.
